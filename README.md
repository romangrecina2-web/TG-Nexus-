# Оболочка ТГ

Проект разделён на frontend и backend:

- `index.html`, `styles.css`, `config.js`, `app.js` — интерфейс GitHub Pages.
- `server.js` и `bot-chat.js` — backend Telegram-бота: Mini App, отправка файлов с кодом и полноценное общение с ИИ в личном чате.

## Общение с ИИ в чате Telegram

Бот принимает обычные текстовые сообщения в личном чате и отправляет их в настроенный OpenAI-совместимый API. История и выбранная модель отдельны для каждого Telegram-пользователя.

Доступные команды (регистр не важен):

- `/chat` — список чатов; активный чат отмечается стрелкой.
- `/add_chat [название]` — создать и активировать чат. Без названия создаётся «Чат 1», «Чат 2» и далее.
- `/chat_equip [название]` — продолжить выбранный чат.
- `/info` — справка по командам.
- `/provider [ID]` — выбрать API-провайдера из каталога; без ID показывает список.
- `/key [ключ]` — сохранить или заменить ключ текущего провайдера. Команду с ключом бот удаляет до сохранения.
- `/model [ID модели]` — выбрать модель вручную; без аргумента открывает общий каталог с поиском и фильтрами.
- `/test` — выполнить реальный короткий запрос к выбранной модели и показать результат или HTTP-ошибку провайдера.
- `/settings` — открыть панель настроек ИИ: подключение, провайдер и модель, лимит ответа, рассуждения, тайм-аут, системная инструкция, интернет-поиск и разрешение JavaScript-песочницы. Изменения синхронизируются с Mini App.
- `/start` и `/help` — открыть Mini App и получить краткую справку.

## Панель настроек в Telegram

Команда `/settings` открывает компактную Rich Message-панель, сгруппированную по разделам:

- **Подключение:** выбранный провайдер, короткий адрес API endpoint, модель и статус API-ключа. Сам ключ в панели не показывается.
- **Параметры ответа:** уровень рассуждений, лимит токенов, тайм-аут запроса и состояние системной инструкции.
- **Инструменты:** интернет-поиск и разрешение JavaScript-песочницы.

Кнопки поиска и песочницы показывают фактическое состояние цветом: зелёный — включено, красный — выключено. После нажатия панель перерисовывается с новым состоянием. Кнопка песочницы при включении запрашивает отдельное подтверждение; сетевой доступ при этом остаётся выключенным. Отключение песочницы также сбрасывает разрешение на её сетевой доступ.

Разрешение песочницы синхронизируется с Mini App, но сам JavaScript-код выполняется только внутри изолированного iframe Mini App, а не в Telegram-чате. Сетевой доступ к песочнице настраивается отдельно. Кнопка «Обновить» вынесена в отдельную широкую строку под панелью; кнопка открытия Mini App расположена ниже неё.

`AI_API_BASE_URL` и `AI_DEFAULT_MODEL` задают стартовые значения по умолчанию. Telegram-бот поддерживает выбор одного из 30 готовых профилей командой `/provider [ID]` или кнопкой в `/settings`; переключение меняет endpoint, протокол и тип авторизации, очищает прежний ключ и сбрасывает несовместимую модель. Затем нужно сохранить новый ключ командой `/key`, открыть каталог через `/settings` → «Модель» или `/model`, выбрать модель и проверить соединение через `/test`. `/key` намеренно не объявляет ключ проверенным: публичный `/models` у некоторых API может отвечать без авторизации. Проверка выполняется реальным запросом генерации через `/test`, где бот показывает HTTP-статус и безопасно очищенное сообщение провайдера. Пользовательские HTTPS endpoint и профили Mini App синхронизируются с Telegram-ботом. `AI_ALLOWED_MODELS` — необязательный резервный список ID моделей через запятую, если провайдер не возвращает каталог. Большинство профилей используют OpenAI Chat Completions; Anthropic подключается через нативный Messages API.

В Telegram кнопка «Модель» открывает отдельный экран каталога с поиском, популярными моделями, фильтрами и карточками характеристик. Каталог запрашивает сведения через API выбранного провайдера; OpenRouter дополнительно предоставляет отдельный запрос подробностей одной модели и серверную сортировку. Характеристики, которых API не возвращает, показываются как «Нет данных» или «Не измерена». Если ключ провайдера отсутствует, каталог предлагает добавить его через ForceReply: сообщение с ключом удаляется до проверки, после чего ключ сохраняется только в зашифрованном хранилище, а каталог загружается автоматически. Состояние меню и поиска сохраняется не более 5 минут; списки моделей, описания и карточки в хранилище не сохраняются.

Ключи пользователей, выбранные модели, история Telegram-чатов, входящая очередь обновлений и очередь исходящих ответов хранятся в одном файле, зашифрованном AES-256-GCM. Запись выполняется через временный файл и атомарное переименование; перед заменой сохраняется предыдущий зашифрованный снимок. Если основной файл повреждён, приложение пробует восстановиться из предыдущего снимка.

Telegram webhook подтверждает получение обновления только после записи в зашифрованную очередь. Повторные update_id отбрасываются. Фоновые обработчики выполняют обновления последовательно в рамках одного пользователя, но могут обслуживать нескольких пользователей параллельно. Ошибки доставки повторяются с ограниченным экспоненциальным интервалом; после лимита попыток событие попадает в dead-letter журнал. Ответы записываются в outbox до отправки: при сбое Telegram повторяется доставка сохранённого ответа, а не сам обработчик команды или запрос к модели. Для шифрования обязательно задайте `BOT_DATA_ENCRYPTION_KEY` — 32 случайных байта в HEX (64 символа) или каноническом Base64 (формат, который генерирует Render `generateValue: true`). В `render.yaml` секрет генерируется платформой автоматически. Сгенерировать значение можно локально командой:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

Ключ шифрования храните только в переменных окружения Render, не в GitHub. Каталог задаётся через `DATA_DIR`. Файловая система Render Free временная: данные могут исчезнуть при пересоздании или переносе сервиса. Очередь и предыдущий зашифрованный снимок используют тот же каталог, поэтому они также не являются долговечными при пересоздании Free-сервиса. Для гарантированного сохранения между деплоями нужен постоянный диск на подходящем платном сервисе или внешняя база данных; проект не переключает тариф и не создаёт платные ресурсы автоматически. Для сохранения ключей и истории между развёртываниями подключите постоянный диск Render и установите `DATA_DIR` в путь его монтирования (например, `/var/data`). Не меняйте `BOT_DATA_ENCRYPTION_KEY` после создания хранилища без переноса и повторного шифрования данных: старый файл станет нечитаемым.

Mini App и Telegram-бот синхронизируют настройки и текстовую историю через `POST /api/sync`. Backend принимает запрос только с действительной подписью Telegram `initData`; CORS дополнительно ограничивает браузерный origin. Общие настройки, API endpoint, выбранная модель, API-ключ и история хранятся в уже существующем AES-256-GCM хранилище. Mini App сохраняет ключ также в Telegram SecureStorage, если клиент поддерживает эту возможность.

Mini App отправляет до 40 последних чатов и до 25 последних текстовых сообщений в каждом. При импорте из Telegram доступны сообщения, хранящиеся на сервере. Текстовые вложения могут попасть в историю как текст; изображения и бинарные файлы между Mini App и Telegram-чатом не передаются. Веб-поиск в боте использует серверный инструмент OpenRouter и включается только для OpenRouter endpoint. Параметры песочницы синхронизируются, но исполнение JavaScript-песочницы доступно только в Mini App.

## Как работает отправка кода

Нажатие на карточку кода в оболочке отправляет сам файл в чат Telegram-бота. Код не добавляется в поле ввода ИИ и не отправляется модели повторно. Стрелка справа в карточке по-прежнему копирует/скачивает содержимое локально.

Backend проверяет `Telegram.WebApp.initData` криптографической подписью с использованием токена бота. Токен хранится только в переменных окружения backend-сервиса и никогда не помещается во frontend.

## Фото в запросах к ИИ

Интерфейс принимает PNG, JPG/JPEG, WebP и GIF. Можно прикрепить до 5 файлов; размер одного изображения — до 700 КБ, общий размер вложений в одном сообщении — до 1,2 МБ. Изображения передаются модели как `image_url` в массиве `content` запроса Chat Completions; текст сообщения ставится перед изображениями.

Для OpenRouter оболочка проверяет каталог `GET /models?input_modalities=image`. Если выбранная модель не поддерживает изображения, только запросы с фото автоматически отправляются через бесплатный роутер `openrouter/free`, который подбирает бесплатную модель с поддержкой изображений. Выбранная в чате модель при этом не меняется. В ответе отображается уведомление о переключении.

Для других OpenAI-совместимых API нужно вручную выбрать модель, у которой входные модальности включают `image`. Если сервер сообщает, что модель не поддерживает изображения, оболочка показывает отдельную подсказку.

## Мультиагентная разработка и JavaScript-песочница

В настройках есть раскрывающийся раздел «Разработка и песочница».

- Мультиагентный режим включается отдельно и применяется к запросам, распознанным как задачи с кодом. Вспомогательные агенты анализируют задачу по разным ролям; основная модель получает их отчёты и формирует итоговый ответ.
- Можно выбрать от 1 до 20 ИИ в команде, включая основную модель. Остальные N−1 агентов получают отдельные специализированные роли. Запросы выполняются группами максимум по четыре, чтобы не отправлять все вызовы одновременно.
- В Mini App можно сохранить до 30 профилей API. У каждого профиля свой адрес, протокол, тип авторизации, модель, список моделей и отдельный ключ в Telegram SecureStorage. Большинство профилей используют OpenAI Chat Completions; Anthropic подключается через нативный Messages API. Для сервисов без /models можно ввести ID модели вручную.
- Вспомогательные агенты распределяются между профилями, для которых на этом устройстве сохранены ключи. Если доступен только один профиль, агенты используют его модели. В Telegram-бот синхронизируется только выбранный активный профиль и его ключ; дополнительные ключи остаются в SecureStorage устройства и не отправляются backend.
- Ключи нескольких профилей хранятся в одном защищённом элементе Telegram SecureStorage. Старый формат с одним ключом автоматически мигрирует при следующем сохранении. Удаление профиля удаляет только относящийся к нему ключ.
- Агентам отправляется текст задачи, недавний текстовый контекст и текстовые вложения. Изображения остаются в контексте основной модели.
- Включение JavaScript-песочницы и её интернет-доступа настраивается раздельно.
- Сетевой режим песочницы разрешает только HTTPS через `fetch`, публичные доменные имена и ответы с поддержкой CORS. Cookies, локальные адреса/IP, `XMLHttpRequest`, `WebSocket` и `EventSource` блокируются; лимит — 10 запросов и 2 МБ ответа за запуск. Тайм-аут настраивается в том же раскрывающемся разделе от 1 до 3600 секунд; значение по умолчанию — 60 секунд.
- Прямой браузерный `fetch` не обходит CORS. Для API без CORS потребуется отдельный контролируемый backend-шлюз. Для production-среды с недоверенным кодом такой шлюз должен дополнительно проверять DNS/IP после каждого перенаправления и ограничивать доступ на серверном уровне.

Каждый вспомогательный агент делает отдельный API-запрос и может расходовать токены. Отчёты агентов являются рекомендациями, а не доказательством корректности; автоматический запуск тестов и совместное редактирование файлов между агентами относятся к следующим этапам архитектуры.

## Публикация frontend

После каждого коммита Pages автоматически обновит файлы сайта.

## Развёртывание backend на Render

1. Создайте новый Blueprint в Render и выберите этот GitHub-репозиторий. В корне уже лежит `render.yaml`.
2. Во время создания сервиса задайте `BOT_TOKEN` значением токена, полученного у @BotFather, и `BOT_DATA_ENCRYPTION_KEY` случайной 32-байтовой hex-строкой. **Не добавляйте секреты в GitHub, config.js или сообщения.**
3. `WEB_APP_URL` и `ALLOWED_ORIGINS` уже описаны в Blueprint. Backend сам создаёт случайный hex-секрет для webhook при запуске и регистрирует его в Telegram.
4. После публикации скопируйте публичный адрес backend-сервиса, например `https://имя-сервиса.onrender.com`. Убедитесь, что `WEBHOOK_SECRET` создан как постоянная переменная Render (Blueprint теперь задаёт `generateValue: true`); не генерируйте новый секрет при каждом запуске.
5. Откройте `config.js` и укажите этот адрес в `apiBaseUrl`, без завершающего слэша:
   ```js
   window.APP_CONFIG = Object.freeze({
     apiBaseUrl: "https://имя-сервиса.onrender.com"
   });
   ```
6. Сохраните и отправьте `config.js` в GitHub. Дождитесь обновления GitHub Pages.
7. Откройте чат с ботом и отправьте `/start`. Backend установит webhook, зарегистрирует команды и покажет кнопку Mini App. После настройки `AI_API_BASE_URL` и `AI_DEFAULT_MODEL` можно общаться с ИИ прямо в личном чате.

Если у сервиса Render меняется публичный адрес, обновите `apiBaseUrl` в `config.js`.

Backend повторно проверяет настройку webhook при временной ошибке конфигурации. `/health` показывает liveness и диагностические счётчики; `/health/ready` возвращает 503, пока не настроены токен, хранилище, очередь и webhook. При получении SIGTERM/SIGINT сервер прекращает принимать новые запросы и пытается завершить активные задачи в течение 20 секунд. Незавершённые задачи восстанавливаются из очереди при следующем запуске, если файловая система сохранилась.

## Лимиты

Для файлов исходного кода в репозитории нет искусственного лимита в 1 МБ. По правилам GitHub:

- GitHub рекомендует держать отдельные Git-объекты примерно до 1 MiB; после 50 MiB Git показывает предупреждение.
- Обычный Git блокирует отдельные файлы больше 100 MiB. Для больших бинарных файлов существует Git LFS, но Git LFS не публикуется через GitHub Pages.
- GitHub Contents API имеет отдельное ограничение возможностей для файлов больше 1 MiB; при работе с такими файлами нужны raw/Git Data операции.

Для отправки сгенерированного файла в чат Telegram используется Bot API `sendDocument`: актуальный лимит Telegram — **50 МБ на документ**. Это ограничение Telegram, а не ограничение GitHub или оболочки.

Отдельно: прикрепление локальных файлов *в запрос к ИИ* в текущей версии всё ещё имеет свои небольшие лимиты и хранится вместе с историей чатов в браузере. Это не ограничивает размер исходников в GitHub или отправляемых ИИ файлов, но такую подсистему хранения нужно отдельно перевести на IndexedDB, прежде чем безопасно повышать её лимиты.

У модели и API-провайдера также есть собственные ограничения на длину контекста и ответа. Они не ограничивают размер репозитория в GitHub.


## Безопасность

- API-ключ Mini App после успешной проверки сохраняется в Telegram SecureStorage на устройстве (Android Keystore / iOS Keychain), если клиент поддерживает эту функцию. Ключ также может синхронизироваться с сервером по HTTPS через `POST /api/sync` после проверки подписи Telegram `initData`; сервер хранит копию в AES-256-GCM хранилище для работы Telegram-бота. Ключ не записывается в `localStorage`, экспорт чатов, журнал приложения или GitHub. Клиент получает серверную копию только в ответе на запрос, авторизованный его собственной Telegram-сессией.
- Ключи Telegram-бота пользователей хранятся отдельно в серверном AES-256-GCM-хранилище; для них нужен секрет `BOT_DATA_ENCRYPTION_KEY` и постоянное хранилище, если данные должны переживать пересоздание Render Free.
- Telegram initData проверяется на backend по HMAC-SHA256; подпись старше одного часа отклоняется.
- Backend ограничивает частоту отправки и размер запросов, а также использует тайм-ауты и защитные HTTP-заголовки.
- JavaScript-песочница работает в отдельном sandboxed iframe без allow-same-origin. Сетевой режим включается отдельно; он ограничен HTTPS, CORS, количеством запросов и размером ответа, но не является серверным DNS/IP-фильтром.

Подробности, ограничения и рекомендации по настройке GitHub/Render см. в [SECURITY.md](./SECURITY.md) и [отчёте обновления](./docs/SECURITY-UPDATE-2026-11-19.md). Перед публикацией запускайте npm test.

- `/promocode CODE` — активировать промокод.
- `/paysupport` — помощь с платежами.

Новый пользователь получает однократный бесплатный PRO-период на 12 дней после принятия актуальных Terms of Service. Для существующих пользователей, уже принявших предыдущую версию условий, пробный период начинается после принятия новой версии. Повторный `/start` не сбрасывает пробный период.

Разовые тарифы: 7 дней — 49 Stars; 14 дней — 89 Stars; 21 день — 119 Stars; 30 дней — 149 Stars. Автоматического продления нет. Купленные дни добавляются к действующему сроку. Расходы на выбранного AI API-провайдера в эти цены не входят.

Платежи проходят через Telegram Stars в валюте `XTR`. Бот отвечает на `pre_checkout_query` отдельным быстрым обработчиком и начисляет доступ только после `successful_payment`. Повторная обработка одного Telegram charge ID не начисляет дни повторно.

По умолчанию `PRO_BILLING_ENABLED=false`: тарифы и пробный период доступны для проверки, но реальные счета не создаются. Включайте `PRO_BILLING_ENABLED=true` только после проверки условий платежей, поддержки и требований к владельцу продукта. Для управления промокодами задайте `BOT_ADMIN_IDS` списком числовых Telegram user ID через запятую. Создание кода: `/promo_create CODE DAYS MAX_USES` (0 — без лимита); отключение: `/promo_disable CODE`; список: `/promo_list`.

Backend хранит PRO-статус и возвращает тариф и доступные возможности в ответе синхронизации. После окончания пробного периода действует Free:
- лимит ответа — 1 200 токенов;
- рассуждения — автоматический режим;
- тайм-аут запроса — до 120 секунд;
- пользовательская инструкция — до 2 000 символов;
- один API-профиль в Mini App;
- поиск в интернете, JavaScript-песочница, сетевой режим песочницы и мультиагентность недоступны.
Обычный чат, собственный API-ключ, выбор модели, память и вложения остаются доступны. PRO открывает лимит ответа до 32 000 токенов, все режимы рассуждений, тайм-аут до 7 200 секунд, инструкцию до 20 000 символов, до 30 API-профилей и до 20 ИИ в мультиагентной команде.

Ограничения проверяются в Telegram backend и применяются при синхронизации Mini App; клиент также блокирует PRO-контролы и инструменты. Mini App отправляет запросы напрямую выбранному пользователем API-провайдеру с его ключом, поэтому локальные клиентские ограничения не являются DRM и не могут служить серверным счётчиком всех внешних запросов.
